# 04-Reuse and Supply Chain Rules

## 一、 四层复用漏斗与正当自研边界

1. **四层复用漏斗顺序**：
   - 第一层：项目已有模块与工具函数（先搜索项目现存实现）；
   - 第二层：语言原生标准库（如 Node.js 原生 test, Python 内置库）；
   - 第三层：已安装第三方依赖（不得引入功能重叠的同类库）；
   - 第四层：正当业务自研（需满足自研门禁）。

2. **正当业务自研门禁（需全部满足）**：
   - 目的仅为避免引入庞大臃肿外部依赖（如为了 1 个函数引入 10MB 库）；
   - 或性能与业务契合度显著超越现有外部通用方案；
   - 必须独立抽取为微型纯函数/模块，零非必要耦合；
   - 必须配备完整的自动化单元测试，覆盖率 100%。

---

## 二、 外部依赖安全准入与 PM 白话背书卡片

1. **自动过滤硬门禁（命中任一默认打回）**：
   - 发布/创建时间 < 30 天；
   - GitHub Star 数 < 100（或 npm/pypi 月下载量极低）；
   - 含有已知未修复 CVE 安全漏洞；
   - 许可证非宽松开源协议（如 GPL 污染商用项目）。

2. **PM 审批白话背书卡片格式**：
   当确需引入外部新依赖且属于正当需求时，Agent 必须生成以下卡片供 PM 审查：

   ```markdown
   ### 📦 外部依赖引入申请卡片
   - **包名与版本**：[库名称] (vX.Y.Z)
   - **大白话用途**：它能帮我们解决什么问题？（禁止专业术语堆砌）
   - **为什么不用标准库/手写**：如果不引入它，我们自己做的代价是什么？
   - **安全性指标**：开源协议（MIT/Apache）、Star数、维护状态、有无已知漏洞。
   - **回滚与替代方案**：如果未来该库停更或出事故，如何无缝替换？
   ```
