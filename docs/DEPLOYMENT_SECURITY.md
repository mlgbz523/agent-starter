# 环境隔离与上线发布安全手册 (DEPLOYMENT_SECURITY.md)

> **使用说明**：规范开发、测试、正式三个环境的权限边界，明确上线前检查与回滚兜底标准。

---

## 一、 三套环境与权限隔离红线

| 环境名称 | 部署位置 | 访问权限 | Agent 权限级别 | 数据库防护策略 |
| :--- | :--- | :--- | :--- | :--- |
| **开发环境 (DEV)** | 本地机器 / 本地 Docker | 仅本地开发者 | **默认开放**（可改动代码、本地验证） | 使用模拟数据，可随时重建 |
| **测试环境 (TEST)** | 内网测试服务器 | 团队内部测试 | **受限操作**（经 PM 确认后可部署） | 独立测试库，每周自动还原备份 |
| **正式生产环境 (PROD)** | 线上公网云服务器 | 真实最终用户 | 🔴 **严禁直接访问**（严禁 Agent 持有线上私钥与直连权限） | 开启物理只读副本，多AZ热备 |

---

## 二、 数据库变更“四步确认机制”
凡涉及修改数据库结构（DDL，如加字段、改类型、分表），必须按以下流程执行，**严禁 Agent 一股脑执行修改**：
1. **生成独立的迁移脚本**（如 `migrations/V1.2__add_status.sql`）；
2. **编写可执行的逆向回滚脚本**（如 `down.sql`）；
3. **在测试环境空跑验证**（Dry-run），确保无锁表死锁风险；
4. **向 PM 提交白话影响面报告**（会不会停机？涉及多少历史数据？），获批后由运维或指定流水线执行。

---

## 三、 上线发布前“五道防线”检查清单 (Release Checklist)

发布上线前，PM 或负责人员只需逐项勾选以下清单：

- [ ] **1. Git 状态核验**：当前分支代码已合并至 `main`，且本地工作区洁净（`git status` 无未提交修改）。
- [ ] **2. 自动化测试全绿**：全量单元测试与集成测试全部 PASS（无任何跳过或报错）。
- [ ] **3. 数据库备份留底**：线上数据库全量快照备份已完成，已记录备份 ID。
- [ ] **4. 锚定回滚版本号**：本次发布已打上规范的 Git Tag（如 `v1.2.0`），上一稳定版本的 Tag 记录在案。
- [ ] **5. 敏感配置隔离**：线上环境变量已通过平台 Secrets 注入，代码仓库中无任何明文硬编码密钥。

---

## 四、 紧急回滚 SOP (Rollback Playbook)
若线上出现不可接受的故障，执行 3 分钟极速回滚：
1. **代码回滚**：直接签出上一稳定版本的 Tag：
   ```bash
   git checkout tags/v1.1.9 -b rollback-release
   ```
2. **容器与部署镜像回滚**：切换至上一稳定版本构建产物，重新发布；
3. **数据库回滚**：若有新加字段引发故障，执行对应的 `down.sql`，必要时从发布前的快照做单点还原。
