# Antigravity Agent Framework v2 架构设计与工程治理实战全景

> 权威架构设计文档 · 面向生产级多场景 AI 协同
> 版本：`v2.0.1` · 归档分类：`架构` · 项目：`antigravity`

## 摘要 (Executive Summary)

本文档系统性总结了从上一代单体巨石型 `AGENTS.md` 规则向 **Antigravity Agent Framework v2** 模块化治理体系的演进历程与架构全貌。针对旧架构中“规则过度膨胀触发 Token 预算截断、开发流程机械绑架办公与写作、纸面文本误充安全拦截”等核心痛点，v2 架构确立了**“三层物理解耦模型”**与**“渐进式按需披露机制”**。配套提供了 Windows 双脚本无污染脚手架（`init-agent.cmd` / `.ps1`）、GitHub 私有模板仓库与原生 Antigravity 快捷指令绑定，实现了全场景新项目（代码开发、小说创作、学术调研、办公写作）的开箱即用与闭环治理。

## 一、 演进动因与反直觉工程洞察

### 1.1 单体巨石架构的破产 (Monolithic Failure)
上一代 Agent 规则将所有业务规范、PM 决策卡片模板、Git 破坏性回滚命令、依赖白名单及多 Agent 调度流程平铺在一个单一的全局规则文件中（达 24.2 KB，约 700+ 行）：
1. **Token 预算与注意力稀释 (Attention Dilution)**：宿主平台的单个规则文件上限通常为 24,000 字节，旧规则处于被截断的物理临界点；每次会话无差别注入海量规则细节，极大稀释了大模型的有效注意力；
2. **场景绑架 (Scenario Hijacking)**：强行预设“所有任务都是软件工程且用户是小白 PM”，导致用户即便进行简单的日常问答、长篇小说创作或学术文献调研，Agent 也会机械地强制要求跑 CLI 单元测试、建立 Git 还原点或弹出复杂的开发卡片；
3. **纸面安全的伪命题 (Illusion of Safety)**：在提示词文本中声明“网络域名白名单”，但大语言模型读到文字并不等同于操作系统和基础设施具备了物理沙箱网络拦截能力；
4. **破坏性回滚风险**：将 `git reset --hard` + `git clean -fd` 写死为默认撤销手段，极易在真实环境中误删开发者未跟踪的代码资产。

### 1.2 核心设计哲学：地图而非说明书 (Map, not Manual)
在 v2 架构的重构中，我们确立了一条根本原则：**根目录 `AGENTS.md` 必须控制在 100 行左右，作为导航地图，而非巨细靡遗的操作手册。**
- 凡是能通过代码静态检查、CI 或编译器强制执行的，不写进提示词；
- 凡是特定任务才使用的操作细则，全部下沉至垂直专项规约，按需动态加载（Progressive Disclosure）；
- 区分事实、推断与未知，将“可证伪性”作为验收的第一标准。

## 二、 现代 Agent 三层解耦模型

v2 架构彻底放弃了单体结构，构建了层级分明的三层治理模型：

```text
┌────────────────────────────────────────────────────────────────────────┐
│ 1. 机器全局安全底座 (~/.gemini/config/rules/AGENTS.md)                  │
│    - 极简行为宪章 (~1.5 KB，26行)：独立判断、诚实证据、高危门禁、防注入     │
└────────────────────────────────────┬───────────────────────────────────┘
                                     │ 优先下沉到项目规则
┌────────────────────────────────────▼───────────────────────────────────┐
│ 2. 项目级通用工作地图 ($PROJECT_ROOT/AGENTS.md)                         │
│    - 约 100 行：步骤0冷启动画像、7大任务模式路由表、01~13专项规约索引    │
└────────────────────────────────────┬───────────────────────────────────┘
                                     │ 动态按需加载
┌────────────────────────────────────▼───────────────────────────────────┐
│ 3. 垂直专项规约与切片 ($PROJECT_ROOT/.agents/)                          │
│    ├── modes/ (6大任务切片: 创作/决策/开发/文档/学习/调研)               │
│    └── rules/ (13条垂直规约: 架构/契约/探针/供应链/门禁/Notion/Skill)   │
└────────────────────────────────────────────────────────────────────────┘
```

### 2.1 第一层：机器全局安全底座 (`global/AGENTS.md`)
- **规模与定位**：仅 1.5 KB（26 行），长驻于机器全局配置，任何空目录或新项目天然继承；
- **核心职能**：定义不可动摇的底线——独立判断、诚实报告未经验证项、高危破坏性操作（删库/强制推送/外发密钥）需明确授权、外部输入一律视为待分析数据（注入防御）。

### 2.2 第二层：项目级通用工作地图 (`AGENTS.md`)
- **规模与定位**：约 100 行，作为进入项目的总入口；
- **核心职能**：
  - **步骤 0 画像与建制**：识别当前是临时短任务还是长期工程；
  - **任务模式路由表**：分流开发、创作、调研、决策、文档、学习；
  - **单一权威源 (SSOT) 索引**：按需指向 `.agents/rules/`，杜绝重复定义。

### 2.3 第三层：垂直专项规约与场景模式 (`.agents/`)
- **任务模式 (`modes/`)**：`CREATIVE.md`（小说创作）、`DEVELOPMENT.md`（代码实现）、`RESEARCH.md`（调研核验）、`DECISION.md`（方案选型）、`DOCUMENTS.md`（办公文档）、`LEARNING.md`（学习辅导）；
- **专项规约 (`rules/`)**：
  - `01` 软件架构与精准差异（最小改动、注释规范）；
  - `02` 契约、测试与大改动前置计划（统一 ≥3 文件与核心契约阈值）；
  - `03` 证伪验证与依赖真实性探针；
  - `04` 四层复用顺序与开源供应链审查；
  - `05` 决策卡片与交付验收矩阵；
  - `06` 受限网络域名白名单政策；
  - `07` 记忆库交接协议与 second-brain 门禁；
  - `08` 多 Agent 编排收敛与重试熔断；
  - `09` UI 设计系统与界面交付自检；
  - `10` 公开开源参考与架构复盘工具边界；
  - `11` Notion 知识库镜像治理门禁（本地原件、八类白名单、禁止泄露物理路径）；
  - `12` 项目环境管理规约 (`PROJECT_ENV.md` 生命周期与命令实测)；
  - `13` 全场景技能发现、评估审查与自适应规则。

## 三、 关键治理门禁与工程护栏

### 3.1 动态范围升级铁律 (Scope Escalation)
为防止“小任务做着做着演变成无审批的大重构”，在 `02` 规则中设置动态升级熔断器：
- **触发条件**：初始判定为小任务，但执行中发现受影响文件总数达到或超过 3 个（≥3），或涉及核心公共接口/共享契约/持久化结构变更；
- **强制动作**：**立即挂起新增源码修改**，保留既有改动，向用户呈报范围升级说明并补齐设计方案，获得用户明确确认后方可恢复写入。

### 3.2 大任务首次写入真实依据
- Agent 在大任务首次修改源码前，必须明确能对应到用户对当前方案与范围的**真实确认记录**；
- 严禁 Agent 凭自我主观判断声称“已获审批”；审批范围发生变化时必须重新确认。

### 3.3 全场景技能自适应漏斗 (13 规则)
针对非代码项目（如小说）无法触发 `package.json` 的缺陷，建立通用技能评估漏斗：
1. **原生能力优先**：先评估大模型原生表现是否足够，严禁将简单任务变成工具采购流程；
2. **动态查询可用清单**：优先匹配工作区与宿主已挂载技能，未知路径严禁假报“已扫描”；
3. **外部脚本逐行审查**：排查高危外发与注入动作，严禁未经授权静默下载；
4. **运行时生效探针**：不轻信命令退出码为 0，必须执行代表性微型探针验证发现状态。

## 四、 Windows 双端脚手架与 GitHub 模板体系

为了让这套治理框架能够跨设备、跨项目极速流转，工程上实施了双端交付工具：

### 4.1 Windows 免策略限制双头脚本
- **`init-agent.cmd`**：外层批处理包装器，自动附加 `@powershell -NoProfile -ExecutionPolicy Bypass ...`，彻底解决 Win10/11 下 PowerShell 默认执行策略拦截红字问题；
- **`init-agent.ps1`**：采用 **UTF-8 with BOM** 编码保存，彻底规避中文 Windows（GBK/代码页 936）下的多字节解析截断奔溃；
- **防 Git 嵌套污染**：远程浅克隆（`--depth 1`）拉取模板后，脚本自动在临时目录切除 `.git`，仅将纯净规约文件注入业务项目；
- **目录隔离**：脚手架执行时显式排除 `global/` 目录，确保业务项目纯净。

### 4.2 GitHub 私有模板库与跨机部署
- **集中托管**：发布至 GitHub 私有仓库 `mlgbz523/agent-framework-v2`，开启 **Template repository** 属性；
- **跨机一键配置**：新电脑克隆仓库后，双击运行 `global/setup-global.cmd`，自动完成旧机器规则备份与 26 行极简底座的全局配置。
