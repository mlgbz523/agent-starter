# 让 AI 真正理解项目：AGENTS.md 实战与项目入口设计

> 实践研报 · 面向项目工程化与上下文闭环
> 归档分类：`调研` · 项目：`antigravity` · 参考源：欧柯Oge实战解析

---

## 摘要 (Executive Summary)

许多开发者在使用 AI Agent 时，常受困于“上下文丢失、组件认知空白、编码规范隐性化、验证闭环依赖人工”四大痛点。本文深入探讨了将 `AGENTS.md` 定位为 **“AI 理解项目的总入口与项目地图”** 的核心逻辑与工程落地方案。通过 Monorepo 仓库聚合、统一环境配置、命令实测闭环、强规则关联自动化检查以及参考项目（reference-projects）机制，建立“规则 ➔ 检查 ➔ 反馈”的现代 AI 编程闭环。

---

## 一、 AI 协同中的四大工程痛点

在多窗口、多仓库、长周期的真实工程协作中，传统人机交互暴露了明显的效率瓶颈：

1. **上下文严重割裂**：早期前后端分仓导致联动开发时频繁切换会话，AI 无法在单窗口感知全局接口定义与调用关系；
2. **内部组件认知空白**：自研组件库或私有 SDK 缺乏显性化定义，AI 极易凭通用经验拼写出不存在的属性或虚构方法；
3. **隐性规范缺乏约束**：团队特有的命名约定、架构分层与异常处理逻辑仅存在于资深工程师脑海中，AI 需反复纠偏；
4. **验证闭环依赖人工**：AI 生成代码后无法自主构建与自测，每次都需要开发者在本地手动跑环境并肉眼核对结果。

## 二、 五大核心工程实践

```text
┌────────────────────────────────────────────────────────┐
│ 1. 仓库聚合 (Monorepo) ─── 提供单窗口全局上下文           │
├────────────────────────────────────────────────────────┤
│ 2. 统一环境 (PROJECT_ENV) ── 消除命令猜测与启动障碍        │
├────────────────────────────────────────────────────────┤
│ 3. 验证闭环 (Verified Loop) ─ 代码写完不算完成，自测通过才算 │
├────────────────────────────────────────────────────────┤
│ 4. 自动化检查 (Linter/CI) ── 将文本口头约定升格为系统强制约束│
├────────────────────────────────────────────────────────┤
│ 5. 参考项目 (References) ──── 源码作为真相，文档作为导航    │
└────────────────────────────────────────────────────────┘
```

### 2.1 实践一：仓库聚合 (Monorepo 架构)
- 将关联的前端、后端、公共契约与自研组件库聚合在同一工作区（通过脚本软链或原生 Monorepo）；
- **核心价值**：AI 能够在单个对话视窗内同时看到接口契约与调用点，修改接口时可同步重构消费端与文档，彻底消除跨仓库的信息孤岛。

### 2.2 实践二：统一环境配置与命令标准化
- 将复杂的编译、构建、健康检查封装为可执行的顶级指令（如 `make build`、`make test`）；
- 集中管理本地环境变量，并在 `AGENTS.md` 中指明配置文件的具体路径；
- **真实性铁律**：写入项目说明的每条测试或启动命令，必须由 Agent 在本地环境实测成功后方可记录，严禁凭历史经验猜测命令。

### 2.3 实践三：严格的自测验证闭环
- **口号升格为纪律**：*“代码写完不算完成，自测通过才算完成”*；
- **接口验证**：统一通过脚本或标准请求工具获取 Token 并调用接口，遵循“步骤分步拆解 + 临时状态传递”；
- **前端验证**：通过无头浏览器工具直接点击操作页面核心路径，观察实际 DOM 与视觉反馈。

### 2.4 实践四：将规则升级为自动化检查
- 凡是能被 Linter、静态类型检查器或架构合规脚本拦截的规则，不依靠提示词口头提醒；
- 自动化检查失败的报错信息中，必须附带**“问题描述 + 修复建议”**，使 AI 能够根据标准错误流自主反思并迭代修复。

### 2.5 实践五：参考项目引入 (Reference Projects)
- 源码是唯一的“真实真相”，文档仅作为“辅助导航”；
- 将核心组件库源码或成熟开源参考项目放入 `docs/_ref/`，并在规则中提供简短的架构索引；
- 确立规则优先级：`自动化检查规则 > AGENTS.md 规则 > 口头约定`。

## 三、 AGENTS.md 的写作规范与原则

1. **控制在 200 行以内（避免信息过载）**：
   - 当什么都重要时，什么都不重要。核心入口只写框架、路径指针与硬底线；
2. **Bad Case 驱动的逆向迭代**：
   - 不要在开工第一天试图写出完美的规则；
   - 每次 AI 出现犯错或越界时，分析根因，逆向推导并追加一条不可违背的具体约束；
3. **强化可执行规则，弱化抽象描述**：
   - 优先记录机器可执行的验证流程与路径指针，避免大量充斥“尽量优雅”、“写出高质量代码”等大模型无法精准度量的模糊废话。
