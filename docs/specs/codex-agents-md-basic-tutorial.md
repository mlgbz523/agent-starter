# 让 Codex 按你的习惯工作：AGENTS.md 基础教程与双场景应用

> 基础速查手册 · 面向研发与通用办公协同
> 归档分类：`速查手册` · 项目：`antigravity` · 参考源：掌舵者AI实验室教程解析

---

## 摘要 (Executive Summary)

`AGENTS.md` 本质上是一份**“面向 AI 的标准化工作说明书与协作宪法”**。在 AI 介入具体任务之前，通过预设规则明确沟通语言、任务工作范围、安全红线、验收标准及个人习惯偏好，能够从源头大幅降低返工、信息泄露与误操作风险。本文档提炼了五项基础规则框架，并详细阐述了如何打破“仅开发者可用”的狭隘认知，实现软件开发与通用办公（文档整理、表格处理、报告撰写）的双场景覆盖。

## 一、 AGENTS.md 的核心五大基本规则

```text
┌────────────────────────────────────────────────────────┐
│ 1. 沟通规则 (Language & Terms) ── 中文沟通，术语保留原样 │
├────────────────────────────────────────────────────────┤
│ 2. 工作范围 (Boundary & Scope) ─ 圈定职责，严禁擅自发挥 │
├────────────────────────────────────────────────────────┤
│ 3. 安全红线 (Safety Guardrails) ─ 高危与敏感信息事前确认│
├────────────────────────────────────────────────────────┤
│ 4. 验收规则 (Verification) ────── 拒绝对齐口头“已完成”   │
├────────────────────────────────────────────────────────┤
│ 5. 个人偏好 (User Preferences) ── 稳定性、可逆性与习惯   │
└────────────────────────────────────────────────────────┘
```

### 1.1 沟通规则：保留关键术语原貌
- **统一自然语言**：默认使用中文沟通、讲解与注释；
- **核心术语原样保留**：代码标识符、终端命令、环境变量、文件名、相对路径与原始报错信息原样保留，禁止机器过度本地化翻译，避免排查定位增加额外认知摩擦。

### 1.2 工作范围：死锁任务边界，抑制自由发挥
- **开发场景**：修复局部缺陷时，严禁顺手大面积格式化或重构相邻无关模块；
- **办公场景**：处理表格或文案时，仅针对指定段落或列执行修改；修改后的成果按规范另存或加版本后缀（如 `客户名单-V2`），未经授权严禁覆盖原始母件；
- **核心逻辑**：严格只做被要求的改动，额外建议必须单独标注为【可选建议（本次不做）】。

### 1.3 安全红线：不可逆与敏感操作的前置阻断
- **敏感数据防外泄**：代码与文档中严禁写入真实 API Key、密码、Token、商业合同或机密客户名单；
- **高危操作显式授权**：批量删除文件、覆盖原有重要数据、清空数据库或执行破坏性 Git 回滚前，必须主动展示影响范围、最坏后果与恢复手段，获得明确批准方可执行。

### 1.4 验收规则：杜绝空洞的自我评价
- 严禁以“我已经全部修好了”、“看起来没问题”等毫无证据的口头结论汇报；
- **开发验收**：必须列明实际执行的命令、真实退出码与测试断言结果；
- **办公验收**：必须清晰列明处理的文件清单、生成的产物路径与尚未核验的不确定项。

### 1.5 个人偏好：沉淀可复用的团队默契
- 明确偏好偏向：如推崇轻量极简解法（YAGNI 原则）、所有操作必须具备回退机制、厌恶过度复杂的嵌套抽象等。

## 二、 基础框架模板与进阶迭代法

### 2.1 极简模板骨架
```markdown
# AGENTS.md

## 1. 沟通方式
- 中文回答，命令、路径、配置与报错保留英文原样。

## 2. 工作范围
- 仅修改用户指定的文件和功能点，不顺带重构无关代码；办公文件不覆盖原件。

## 3. 安全红线
- 不外泄 API Key 或私有凭据；删除、覆盖文件前必须确认。

## 4. 验收标准
- 汇报实际命令和结果，不拿“无报错”代替测试成功。

## 5. 工作偏好
- 优先原生简单实现，改动保持最小必要差异。
```

### 2.2 渐进式迭代法则 (Bad Case Driven)
- **初始阶段勿求全**：先搭载上述 5 条核心规则开工；
- **犯错反向补充**：一旦发现 AI 覆盖了源文件，立即追加一条具体的禁止覆盖条目；一旦发现 AI 虚构了测试，立即追加一条退出码核验规则；
- 规则经过 2~3 周的真实踩坑迭代后，将逐渐贴合开发者与团队的工作节奏，协同成本显著降低。
