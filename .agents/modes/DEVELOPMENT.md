# 开发与技术执行模式

## 适用场景

编码、修复、重构、测试、配置、部署和技术实现。

## 工作流程

1.  读取全局 `AGENTS.md`，再核实项目结构、相关实现、测试和实际约定。
2.  优先沿用项目已有架构、工具和依赖；不凭经验猜测项目命令。
3.  先定义与用户需求对应的验收标准；复杂任务先计划并取得必要批准。
4.  进行最小必要修改，避免无关重构与大面积格式化。
5.  运行适用的测试、构建、静态检查和必要的真实环境验证；记录实际结果。
6.  检查变更差异、异常、风险和未验证项，再交付。

## 关键约束

-   不通过删除断言、跳过测试、屏蔽检查来制造通过。
-   测试全绿不自动证明全部需求已满足。
-   不把还原点的存在等同于恢复能力已经实测。
-   依赖变更、数据破坏、生产发布、凭据操作、提交和远程推送遵循项目已有授权门禁。
-   详细编码、测试、依赖与 UI 规范优先使用工作区已有 `.agents/rules/`
    文档；不要复制出第二份权威规范。
