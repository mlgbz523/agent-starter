# 07-memory-bank-protocol.md - 状态机持久化与会话物理阻断规约 (Memory Bank SOP)

> **目标**：彻底解决大模型在长时间复杂对话后注意力稀释（Attention Dilution）、错误级联中毒（Context Poisoning）及终端日志过载导致的幻觉问题。
> **核心原则**：**长对话必衰退，状态机落盘换新会话（New Chat）是最高性价比的物理级抗幻觉方案。**

---

## 一、 触发条件（何时建议物理切换会话）

当满足以下任一条件时，Agent 必须主动向 PM 发起【会话物理归档与切换建议】：
1. **重大里程碑完成**：当前阶段性目标完成、准备启动全新模块或全新业务功能时；
2. **错误熔断触发**：本次会话中已累计触发过 2 次同类错误熔断；
3. **PM 显式指令**：PM 明确说“归档 / 切换会话 / 新会话 / New Chat”；
4. **轮次辅助参考**：当前会话交互超过 20 轮时作为辅助参考信号向 PM 提示，但不单独作为强制阻断条件。

---

## 二、 会话无缝交接三步法 (Handoff Pipeline)

当达到切换条件时，Agent **严禁直接断开**，必须执行以下标准化交接流水线：

### 1. 第一步：状态全量落盘 (State Persistence)
- 强制更新 `docs/PROGRESS.md`，将当前会话提炼为：
  - 【已完成清单】：精确到具体修改的文件与实测结果；
  - 【未完成与进行中】：明确下一阶段具体从哪一行代码或哪个测试开始；
  - 【最后已知 Commit】：记录当前 `git rev-parse --short HEAD` 的编号；
  - 【重大决策锚点】：同步关键技术选型至 `docs/DECISIONS.md`。

### 2. 第二步：呈报交接卡片 (PM Handoff Card)
向 PM 发出极简交接指令，例如：
```markdown
### 🔄 会话状态机归档就绪（建议开启新会话）
- **触发原因**：当前阶段里程碑已完成，为保障后续编码推理处于最高纯净度，已执行 Memory Bank 状态固化。
- **账本同步状态**：核心进展、实测证据与未尽事宜已 100% 写入 `docs/PROGRESS.md`。
- **操作指引**：
  1. 点击 IDE 界面上的「新建对话 / New Chat」；
  2. 在新对话输入：“**继续按照 docs/PROGRESS.md 推进**”；
  3. Agent 将在 0 杂质、满血状态下秒级无缝续接。
```

### 3. 第三步：新会话冷启动极速恢复 (Cold Start Recovery)
在任意新会话中，Agent 的首轮动作规范：
1. **第一优先级读取**：静默读取 `docs/PROGRESS.md` 顶部的【进度速览区】；
2. **确认环境基线**：比对 `PROGRESS.md` 中记录的最后 Commit 编号与当前 `git rev-parse --short HEAD`；若不一致，告知 PM“工作区在上次会话后有外部改动”；再运行 `git status -s` 确认工作区是否干净；
3. **一句话唤醒汇报**：“*已根据 `docs/PROGRESS.md` 完成上下文复原，当前停留在【XXX 任务】，准备执行【YYY】，是否继续？*”
