# 02-Contract and Testing

## 1. 契约先行
- 编码前先定义并锁定数据模型接口（按项目语言选用，如 TypeScript Interface、Pydantic 等）。

## 1-B. 大功能先出设计图（强制）
- 触发：改动超过 3 个文件（与三红线第③条同一门槛），或新增模块 / 持久化数据 / 核心流程变化。纯界面任务只走 09，不重复触发。
- 动作：写任何代码前，先在 `docs/design/<功能名>.md` 产出设计图（优先 Archify；不可用则把 Mermaid 图写入该文件）。对话中只给 2~3 行结论 + `file:///` 路径，严禁在对话里倾倒图的源码。
- 汇报：按 05 的「轻量汇报」列出"新增 / 修改 / 不动"的模块，等 PM 回复"确认"。设计图作为 `docs/task_plan.md` 的组成部分，与方案一次提交、一次批准，不另设第二道确认。
- 顺序：方案与设计图一并获批 → 契约（§1）→ 测试 → 实现。PM 未确认前，不得修改任何源码文件。

## 2. 验收门禁
- 严禁以“已写完”结项；必须终端运行 CLI 测试命令（如 `pytest` / `npm test`）并提供真实 PASS 终端输出。
- **验证命令真实证伪能力**：验证命令必须具备证伪能力——故意破坏关键逻辑后测试必须能够报错抓出；严禁吞退出码、严禁使用 `|| true`、严禁仅用 `echo` 伪造通过。

## 2-B. 无测试框架时的最小测试底座
- 新项目若尚无测试框架，Agent 必须先搭建最小测试底座（如 Node 原生 `node --test`、Python `pytest`）并在 `docs/PROJECT_ENV.md` 记录；
- 交付前必须运行**全量**测试套件（不只是新增用例），确保整体无回归。

## 3. 禁止测试作弊 (No Test Tampering)
- 🚫 严禁为了让测试变绿而篡改/删除既有断言、添加 `@skip`、或关闭代码检查规则；
- 确因需求变更需调整测试，必须在 `docs/task_plan.md` 中说明理由并经 PM 批准。
