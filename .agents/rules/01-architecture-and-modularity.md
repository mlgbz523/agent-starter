# 01-Architecture and Modularity

## 1. 极简主义与单一职责 (KISS & SRP)
- **架构极简**：每个模块承担单一明确职责，严禁隐式全局状态污染。
- **核心编码偏好（常驻，不依赖外部服务）**：
  1. 优先使用语言原生标准库与项目既有模块，拒绝过度抽象与投机性灵活；
  2. 纯函数与明确输入输出优先，严禁隐式全局状态污染；
  3. 增量修改遵循外科手术式行级编辑，保持 Git Diff 绝对干净。
- `second-brain` 中的偏好条目仅作补充，与本节冲突时以本节为准。

## 2. 外科手术式修改 (Surgical Diff)
- **严禁全量重写**：修改已有文件必须使用行级精准编辑工具定位替换，仅生成最短有效变更。
- **严禁顺手格式化**：严禁借修改核心逻辑之名，顺手重排相邻无关代码的缩进、换行或空行，确保 Git Diff 绝对干净。

## 3. 定向检索与语义块读取 (Targeted Search First)
- **终端关键词锁定**：检索目标优先使用终端或检索工具定位关键词行号；
- **语义块优先读取**：单次读取以完整函数或独立语义块为限（原则上不超过 300 行），严禁未定位关键词直接读取全文件；
- **反对机械切片**：以理解业务上下文为导向，避免将常规连续逻辑人为切成碎段读取，优先保持语法树与上下文连贯。

## 4. 纯净代码与精简注释 (Code Purity)
- **精简 Why 注释**：仅保留关键边界与复杂逻辑的 Why 说明，严禁行级废话注释。

## 5. 流派仲裁协议 (Style Routing Protocol)
- **代码与后端实现（逻辑层）**：默认锚定 **Karpathy 极简铁律**（四层复用漏斗顺序见 [04-reuse-and-supply-chain.md](04-reuse-and-supply-chain.md)；拒绝过度抽象与投机性灵活）。
- **界面与用户体验（表现层）**：界面实现一律遵循项目根目录 `DESIGN.md`（若存在）；无 `DESIGN.md` 时默认采用 **现代高质感工程规范**。
- **互斥流派动态分流门禁**：
  - **极简代码模式 (Ponytail)**：仅当 PM 在提示词中显式声明“极简代码 / 原生实现 / 性能优先 / ponytail”时，降级所有动效与装饰组件，采用最简原生代码；
  - **高级动效 (Motion/Cinematic)**：仅当 PM 在提示词中显式声明“动效 / 宣传片 / 炫酷 / onetake”时，动态挂载复杂弹性微交互与动画库。
