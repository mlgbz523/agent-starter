# 05-PM Interaction Templates

> **使用宗旨**：所有面向 PM 的交互，Agent 必须以“PM 具备业务常识但无技术判断力”为前提，替 PM 准备好全部决策条件。
> 🔒 **可点击链接刚性规范**：凡在卡片、看板或汇报中向 PM 呈示文件或目录，**严禁使用相对路径 `[xxx](path/xxx)`**，必须统一强制使用 `file:///` 协议及工作区绝对路径格式（Windows 统一使用正斜杠 `/`；路径含空格时统一编码为 `%20`，如 `[文件](file:///C:/Users/User%20Name/docs/PROGRESS.md)`），彻底杜绝 Webview 预览时触发 `GetFileAttributesEx` 错误。
> 📋 **模板库契约**：卡片排版严格遵循本规约第“一、卡片核心契约与必备要素”标准结构输出，优先使用本地已沉淀模板，无需前置网络阻塞检索。
> 🛡️ **豁免项**：全局工作区治理自举卡片（Workspace Governance Bootstrapper）为一次性工程初始化场景，不要求满足决策卡片 6 要素；其模板以全局 `AGENTS.md` §1.2 为准。

---

## 一、 卡片核心契约与必备要素

1. **PM 决策卡片 (Decision Card) 6 要素（缺一不可）**：
   - ① 一句话白话冲突与要决定的事；
   - ② 任务起始还原点编号；
   - ③ `docs/PROGRESS.md` 看板已同步状态；
   - ④ 3~5 条白话验收标准（就地展示，严禁甩链接）；
   - ⑤ 双选项对比（耗时/成本/改动难易/官方一手状态）；
   - ⑥ Agent 明确推荐与最坏撤销手段（安全还原至任务开始前的还原点）。

2. **高危操作审批申请卡片 (Approval Request)**：
   - **高危操作定义**：严格参照全局 `AGENTS.md` §〇-B 高危操作清单（删除文件/目录、`reset --hard`、强推、修改依赖锁文件、变更环境变量/密钥、数据库写操作或结构变更、对外发送数据）；
   - **必备要素**：包含申请操作、业务影响面、最坏后果、能否安全撤销及 Agent 明确建议。未明确获批前严禁执行。

3. **交付完成声明与去伪存真验收看板 (PM Completion Sign-Off)**：
   - **四要素验收矩阵**：需求原话、对应测试行号、正向测试、证伪/反向边界验证、真实环境真机验证（必须附带真实命令输出或截图路径，PM 需可独立核对，严禁 Agent 自评）、判定结论（✅真正已验证 / ⚠️未验证 / ❓不确定）；
   - **三分法看板**：✅ 已验证 / ⚠️ 未验证 / ❓ 不确定（诚实准则，严禁含糊）。

4. **熔断受阻与错误报告卡片 (Block Report)**：
   - 触发 2 次错误熔断时输出：一句话白话卡在哪里、已尝试动作、4条可选出路（缩小范围/换方案/人工协助/暂缓）及明确推荐。

5. **零基础可执行演示步骤 (Zero-Barrier Demo)**：
   - 严格三段式：打开哪里 ➔ 点什么 ➔ 应该看到什么。

6. **汇报分级门禁 (Report Sizing)**：
   - **轻量汇报（≤3 行）**：未命中三红线的小改动，仅输出“改了什么 + 实测结果”；
   - **完整看板**：命中三红线的大任务或 PM 显式要求时，使用完整四要素验收矩阵与三分法看板。
