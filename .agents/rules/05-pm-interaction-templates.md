# 05-PM Interaction Templates

> **使用宗旨**：所有面向 PM 的交互，Agent 必须以“PM 具备业务常识但无技术判断力”为前提，替 PM 准备好全部决策条件。
> 🔒 **可点击链接刚性规范**：凡在卡片、看板或汇报中向 PM 呈示文件或目录，**严禁使用相对路径 `[xxx](path/xxx)`**，必须统一强制使用 `file:///` 协议及工作区绝对路径格式（Windows 统一使用正斜杠 `/`），彻底杜绝 Webview 预览时触发 `GetFileAttributesEx` 错误。
> 🧠 **模板库托管**：具体 Markdown 卡片详细排版代码与表格样例已移入 Second Brain 统一托管，通过 Recall Hooks ④ 自动按需召回。

## 一、 卡片核心契约与必备要素

1. **PM 决策卡片 (Decision Card) 6 要素（缺一不可）**：
   - ① 一句话白话冲突与要决定的事；
   - ② 任务起始还原点编号；
   - ③ `docs/PROGRESS.md` 看板已同步状态；
   - ④ 3~5 条白话验收标准（就地展示，严禁甩链接）；
   - ⑤ 双选项对比（耗时/成本/改动难易/官方一手状态）；
   - ⑥ Agent 明确推荐与最坏撤销手段（安全还原至任务开始前的还原点）。

2. **高危操作审批申请卡片 (Approval Request)**：
   - 包含申请操作、业务影响面、最坏后果、能否安全撤销及 Agent 明确建议。未明确获批前严禁执行。

3. **交付完成声明与去伪存真验收看板 (PM Completion Sign-Off)**：
   - **四要素验收矩阵**：需求原话、对应测试行号、正向测试、证伪/反向边界验证、真实环境真机验证、判定结论（✅真正已验证 / ⚠️未验证 / ❓不确定）；
   - **三分法看板**：✅ 已验证 / ⚠️ 未验证 / ❓ 不确定（诚实准则，严禁含糊）。

4. **熔断受阻与错误报告卡片 (Block Report)**：
   - 触发 2 次错误熔断时输出：一句话白话卡在哪里、已尝试动作、4条可选出路（缩小范围/换方案/人工协助/暂缓）及明确推荐。

5. **零基础可执行演示步骤 (Zero-Barrier Demo)**：
   - 严格三段式：打开哪里 ➔ 点什么 ➔ 应该看到什么。
