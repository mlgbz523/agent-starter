# 05 — 决策与交付模板

> 目标是让用户能依据完整信息做决定，而不是让每个小任务都被卡片和看板拖慢。

## 适用范围
只在需要用户拍板、工作区要求审批、任务命中重大变更门禁或用户明确要求完整验收时使用。简单、低风险、可逆的工作采用轻量汇报。

## 1. 决策卡片

重大分支决策卡片包含：
1. 用业务语言说明要决定的事情和冲突；
2. 任务起始状态/还原依据（如已实际记录）；
3. 进度状态（仅当项目采用并已同步看板时填写）；
4. 3–5 条可核验验收标准；
5. 主要选项的成本、影响、风险和可逆性；
6. Agent 的明确推荐、依据、未知项与最坏撤销办法。

不适用的字段要说明原因，不能捏造提交编号、还原点或看板已同步状态。将一个决定拆分到多个维度时，优先分开呈报，避免打包强迫用户一次批准所有事项。

## 2. 高风险操作审批

在删除/覆盖重要资料、对外发送数据、使用付费服务、修改权限、修改生产/数据结构、处理秘密、提交/推送等操作前，按工作区规则确认授权。申请要说明操作内容、影响范围、最坏后果、回滚/恢复办法和 Agent 建议。

用户已明确授权的范围，不应再次重复索要同一授权；若执行过程中风险或影响范围实质扩大，应暂停扩大的部分并重新确认。

## 3. 交付验收矩阵

复杂任务或用户要求完整验收时，采用以下列：

| 需求/目标 | 对应产物或检查 | 正向证据 | 反向/边界证据（适用时） | 真实环境/人工核验（适用时） | 状态 |
|---|---|---|---|---|---|

状态只使用：**已验证 / 未验证 / 不确定**。按风险和任务性质选择证据；不存在“任何任务必须同时提供测试行号、反向测试和真机截图”的通用要求。

## 4. 错误熔断与阻塞报告

若同类问题多次尝试仍无进展，停止盲目重复，简明报告：卡点、已经尝试的动作和结果、当前判断、可选出路（缩小范围/换方案/人工协助/暂缓）及推荐方案。具体重试上限由相关任务规则或实际成本决定；若工作区采用 2 次上限，按该策略执行。

## 5. 零基础演示步骤

面向非技术用户的演示使用：**打开哪里 → 点什么/输入什么 → 应该看到什么**。只有需要演示的任务才要求此格式。

## 6. 汇报分级

- 小型任务：简述改动/产物与实际检查结果；
- 复杂任务、重大决定或用户要求完整验收：给出清单/矩阵、证据、未验证项和风险。

## 7. 文件链接格式

- 规则/文档源码之间优先使用相对路径，保持仓库可移植性。
- 对话中的 `file:///` 绝对路径仅在当前客户端确实支持、已知本机路径并且用户需要直接打开本地文件时使用；Windows 路径用正斜杠并对空格正确编码。
- 未核实绝对路径或客户端支持情况时，使用准确的工作区相对路径并说明如何定位，不要伪造可点击链接。
