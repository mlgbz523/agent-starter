# 08 — 多 Agent 与调度收敛

## 适用范围
只有在当前环境实际提供多 Agent、团队协作或深度代理能力，且任务复杂度值得使用时适用。单 Agent 环境不得声称已创建子代理或完成独立复核。

## 1. 单兵优先

- 默认由单个 Agent 完成边界清晰、局部且可自包含的任务。
- 仅在多个独立模块可并行、需要不同领域独立分析，或确有大规模并行调研/对抗评审价值时使用多 Agent。
- 是否“超过 3 个模块”可作参考信号，不是自动启动团队的充分理由；必须考虑协调成本、重复工作和文件冲突风险。

## 2. 约束继承与复核

- 派发任务时，将与任务有关的硬约束显式传递给子代理：安全/数据边界、域名策略、密钥处理、危险操作授权、测试证据和重试限制。
- 主代理不能仅凭子代理口头汇报就宣布完成；对关键结论应独立核对产物、命令输出、证据或来源。
- 并行子代理不得同时编辑同一个文件，除非已明确分配冲突解决方式。
- 子代理可访问哪些文件和网络，取决于实际工具权限；提示词约束不等于技术权限隔离。

## 3. 评审轮次控制

- 可将最多 2 轮作为普通实现/审查迭代的预算，以防无限找茬；这是收敛策略，不得压制新发现的安全、数据丢失或契约破坏等阻断问题。
- 达到轮次上限后仍有非阻断性建议时，汇总取舍并请用户决定是否继续。
- 若仍有阻断性风险，明确标记未完成并请求决策，不能为了满足轮数限制而忽略风险，也不应无限循环。

## 4. 深度代理与重试

- 下发任务前补全具体目标、相关路径、关键事实、输出格式和验收条件，不能只传“继续上一个任务”等脱离上下文的代词。
- 若两次追加尝试仍未解决同类失败，停止盲目重试，呈报根因判断、已尝试动作和选项。新证据出现或方案发生实质变化时，可在说明理由后重新制定策略。
