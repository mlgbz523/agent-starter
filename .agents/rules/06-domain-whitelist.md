# 06 — 网络域名白名单

## 适用范围与边界
这是**工作区网络安全策略**，不是所有项目和所有研究任务都天然共用同一份域名名单。若当前工作区明确启用此白名单，外部网络访问必须遵守本文件；其他工作区应使用其自己的正式策略，不得把本文件的名单当作普遍适用的全球白名单。

## 1. 本工作区已登记域名

| 域名 | 用途 | 维护责任 |
|---|---|---|
| `api.github.com` | GitHub 技能生态检索与元数据 | Agent / PM |
| `github.com` | 公开官方仓库 | Agent / PM |
| `registry.npmjs.org` | Node.js 包元数据 | Agent / PM |
| `pypi.org` | Python 包元数据 | Agent / PM |
| `api.notion.com` | 已授权的 Notion 知识库读写 | Agent |
| `gitdiagram.com` | 公开仓库架构图浏览（仅在用户明确要求且策略允许时） | Agent / PM |

域名在名单中并不等于任何数据都可以发送到该服务；数据分类、凭据处理、权限和用户授权仍然有效。

## 2. MCP 与外部服务

- MCP 或其他代理工具发起的网络请求也适用当前工作区的白名单及数据外发规则。
- 端点域名不在名单内时先停止该请求，说明所需域名、用途、将发送的数据类型与风险，并按工作区审批流程申请。
- 私有端点不得写入会随模板公开分发的文件；本工作区可用 `.agents/rules/06-domain-whitelist.local.md` 保存本地补充名单，并确认其已被版本控制忽略。不要在此文件写秘密或令牌。
- 官方来源优先用于核验官方行为、版本和政策；社区与二手来源是否允许，依任务目标和工作区网络政策判断。不能把二手来源伪装成官方事实。

## 3. 新域名审批

如本工作区要求逐域名审批，首次访问新官方文档主域名或任何未登记域名前，先说明域名和用途并等待批准。只有工具确实支持域名限制时，这条文档规则才构成配置外的补充，不能声称仅靠文字就实现了技术层的网络拦截。

严禁扫描内网或将私有代码、密钥、内部日志及非必要个人数据发往未获批准的外部服务。
