# 13 — 技能发现与生命周期管理

## 适用范围
适用于所有项目类型（包括软件开发、小说创作、学术调研、办公写作与数据分析）。当现有能力不足以支撑高质量交付，或用户要求扩展 Agent 能力时生效。

## 1. 原生能力优先原则

- 发现功能或流程缺口时，**优先评估大模型当前的原生能力是否足以高质量解决**；
- 只有当外部 Skill 能带来实质性的专业流程增强、工具集成或显著降低认知负荷时，才发起外部 Skill 检索与适配评估；
- 严禁将简单的创作、问答或文字处理任务变成无意义的外部工具采购流程。

## 2. 动态能力检索漏斗

按以下严格顺序逐层发现与适配技能：

1. **当前工作区已载入技能**：优先使用项目 `.agents/skills/` 中已存在的技能；
2. **宿主运行时可用技能**：动态查询当前 Agent 运行环境已挂载的内置或全局技能清单；不硬编码假定特定文件路径，未知路径严禁报告为“已扫描”；
3. **受信生态检索**：仅在本地能力确实不足且工作区网络策略允许时，在官方注册表或受信来源中检索候选 Skill；
4. **模型原生方案**：若无匹配的成熟外部 Skill，回退至纯模型原生能力，并向用户说明能力边界。

## 3. 外部 Skill 审查与安装门禁

发现匹配的外部候选 Skill 时，必须完成以下审查并向用户呈报【Skill 引入申请】：

- **来源与维护**：官方/受信作者、仓库星标、更新时间、是否已废弃；
- **脚本与动作**：逐行审查 Skill 中包含的可执行脚本（Python/Bash/Node 等），排查高危操作（如网络外发、任意文件写入、系统指令注入）；
- **权限与环境**：声明该 Skill 需要的工具权限、环境变量和依赖；
- **许可证兼容性**：遵守项目许可证政策。

🔒 **绝对禁令**：**严禁未经用户明确批准静默下载或安装任何外部 Skill**。安装时优先采用工作区级隔离安装，不污染机器全局环境。

## 4. 运行时生效核验

- 安装或载入 Skill 后，**不得以“文件已写入”或“下载命令退出码为 0”直接宣称生效**；
- 必须通过宿主运行时的技能发现机制确认该 Skill 已被识别（如技能清单可见、或通过最小代表性探针任务调用测试）；
- 探针调用失败时，如实报告故障原因，并提供回滚或人工介入方案。
